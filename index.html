High Priority Engineering Mathematics
~15 marks ▶

What to Revise

  • Linear Algebra — rank, nullity, eigenvalues, Cayley-Hamilton theorem
  • Calculus — limits, continuity, maxima/minima, definite integrals
  • Probability — Bayes' theorem, conditional probability, distributions (Binomial, Poisson, Normal)
  • Statistics — mean, variance, standard deviation

Formulas That Appear Every Year

P(A|B) = P(A∩B) / P(B) ← Bayes, every single year E[X] Binomial = np, Var = np(1−p) E[X] Poisson = λ, Var = λ det(AB) = det(A)·det(B) If Av = λv → A⁻¹v = (1/λ)v Rank-Nullity: rank(A) + nullity(A) = n
Strategy Don't re-derive. Memorise the output forms. GATE maths questions are pattern-recognition, not original derivation. 20 previous year questions beats 3 hours of theory.
High Priority Data Structures & Algorithms
~10–12 marks ▶

Highest-Yield Topics

  • Sorting — time complexities, stability (Merge = stable, Quick = not), when each is best
  • Trees — height, traversals, BST operations, AVL rotations (LL/RR/LR/RL)
  • Graphs — BFS/DFS, Dijkstra, Bellman-Ford, topological sort (DAG only)
  • Hashing — open addressing, chaining, load factor, collision resolution
  • Heaps — build-heap O(n), heap sort O(n log n), min-heap vs max-heap
  • Recurrences — Master theorem (commit to memory)

Master Theorem — Quick Reference

T(n) = aT(n/b) + f(n) Case 1: f(n) = O(n^(log_b(a)−ε)) → T(n) = Θ(n^log_b(a)) Case 2: f(n) = Θ(n^log_b(a)) → T(n) = Θ(n^log_b(a) · log n) Case 3: f(n) = Ω(n^(log_b(a)+ε)) → T(n) = Θ(f(n)) Common: T(n)=2T(n/2)+n → Θ(n log n) [Merge Sort] T(n)=T(n/2)+1 → Θ(log n) [Binary Search]

GATE Question Patterns (Predict the Question)

  • "Trace algorithm on input X" — go step by step, don't assume
  • "Worst-case complexity of Y" — know amortized analysis too (dynamic arrays)
  • Tree height / number of nodes — formulaic, fast 2 marks
  • Which sorting algorithm is stable? — a favourite trick question
High Priority Operating Systems
~8–10 marks ▶

Focus Areas

  • Process scheduling — FCFS, SJF (preemptive = SRTF), Round Robin, Priority. Calculate waiting time, turnaround time.
  • Deadlock — four necessary conditions, Banker's algorithm (frequently numerical)
  • Memory — paging, segmentation, TLB hit/miss, page replacement (LRU, FIFO, Optimal)
  • Synchronisation — semaphores, monitors, Peterson's solution, producer-consumer
  • File systems — inode structure, FAT, disk scheduling (SSTF, SCAN, C-SCAN)

Banker's Algorithm — The Formula You Need

Need[i][j] = Max[i][j] − Allocation[i][j] Safe state ↔ a safe sequence exists Algorithm: find a process whose Need ≤ Available release its resources, repeat If all processes finish → safe state
Deadlock Coffman Conditions — Four of Four Mutual Exclusion · Hold & Wait · No Preemption · Circular Wait. All four must hold simultaneously for deadlock. GATE asks "which condition is violated by resource X" — know each one's definition.
High Priority DBMS
~8–10 marks ▶

Must-Cover Topics

  • Normalisation — 1NF, 2NF, 3NF, BCNF. Given FDs, identify what form the relation is in.
  • Functional Dependencies — closure, minimal cover, Armstrong's axioms
  • SQL — joins (inner/outer/natural), GROUP BY, HAVING, nested queries, aggregates
  • Transactions — ACID, conflict serializability, view serializability, 2PL
  • Indexing — B+ tree height and search, hash indexing

FD Closure Algorithm

To find (A)⁺: 1. Start: result = {A} 2. For each FD X→Y: if X ⊆ result, add Y to result 3. Repeat until no change → If (A)⁺ = all attributes → A is a superkey
Conflict Serializability Shortcut Draw the precedence graph. If there's a cycle → not conflict serializable. No cycle → conflict serializable. 2PL always produces conflict-serializable schedules (converse not always true).
High Priority Computer Networks
~7–9 marks ▶

Hot Topics

  • IP addressing — subnetting, CIDR, number of usable hosts
  • TCP — 3-way handshake, flow control, congestion control (slow start, AIMD)
  • Routing — Dijkstra's (link state), Bellman-Ford (distance vector), count-to-infinity
  • MAC protocols — CSMA/CD, ALOHA efficiencies

Formulas That Come Every Year

Pure ALOHA efficiency = G·e^(−2G), max ≈ 18.4% at G=0.5 Slotted ALOHA efficiency = G·e^(−G), max ≈ 36.8% at G=1.0 Subnetting: usable hosts = 2^(32−prefix) − 2 Bandwidth-delay product = Bandwidth × RTT Propagation delay = Distance / Speed
High Priority Theory of Computation
~7–8 marks ▶

The Chomsky Hierarchy — Memorise This Table

Type 0: Recursively Enumerable → Turing Machine Type 1: Context-Sensitive → Linear Bounded Automaton Type 2: Context-Free → Pushdown Automaton Type 3: Regular → DFA / NFA / ε-NFA

Closure Properties (Tested Directly)

  • Regular — closed under union, concat, star, complement, intersection, difference
  • CFL — closed under union, concat, star. NOT closed under complement or intersection
  • CFL ∩ Regular = CFL (intersection with a regular language IS closed)
  • CSL — closed under all boolean operations
  • RE (Type 0) — closed under union, concat, star, intersection. NOT complement.

GATE Favourite Question Types

  • DFA minimisation via table-filling (equivalence classes method)
  • "Is this language regular?" — use Pumping Lemma to disprove regularity
  • Decidability — Halting problem is undecidable. Know Rice's Theorem.
  • NFA to DFA conversion — subset construction
Rice's Theorem (Free Marks Every Year) Every non-trivial semantic property of Turing machines is undecidable. "Does this program halt on X?" = undecidable. "Does this program accept any string?" = undecidable. Know how to identify semantic vs syntactic properties.

Core Areas

Key Formulas

Euler's Formula (planar connected graph): V − E + F = 2 Simple planar graph: E ≤ 3V − 6 No triangles (bipartite): E ≤ 2V − 4 Handshaking lemma: sum of all degrees = 2|E| Eulerian circuit exists ↔ all vertices have even degree
High Priority General Aptitude
15 marks ▶

Free Marks — Take Every Single One

15 marks that require zero CS knowledge. The only exam section where a well-rested brain beats a well-studied one. Drill 3–4 years of previous GATE aptitude sections.

Sections

  • Verbal — reading comprehension, fill in the blanks, sentence correction, synonyms/antonyms
  • Quantitative — percentages, ratios, averages, time-speed-distance, work-rate, profit-loss
  • Logical reasoning — syllogisms, number series, blood relations, directions, coding-decoding
Exam-Room Strategy Attempt aptitude after clearing your confident CS questions. Fresh eyes catch verbal traps that a tired CS-mode brain misses. Quantitative questions are Class 10 maths wearing a suit — don't overthink them.

Medium Computer Organisation & Architecture
~5–7 marks ▶

Focus Only On These

  • Cache — direct mapped, set associative, fully associative. Calculate hit ratio and average access time.
  • Pipeline — stages, structural/data/control hazards, stall cycles, speedup formula
  • Number representation — 2's complement arithmetic, IEEE 754 floating point
  • Addressing modes — immediate, direct, indirect, indexed, register
  • I/O — DMA vs interrupt-driven vs programmed I/O
Cache avg access time = h×T_cache + (1−h)×T_memory Pipeline speedup = n×k / (k + n − 1) where n = instructions, k = pipeline stages
Medium Compiler Design
~5–6 marks ▶

What GATE Actually Asks

  • Lexical analysis — regex to NFA/DFA, token recognition
  • Parsing — FIRST and FOLLOW sets, constructing LL(1) parse table
  • LR parsing — SLR, LALR, Canonical LR. Which grammars each handles.
  • Syntax-directed translation — S-attributed vs L-attributed grammars

FIRST/FOLLOW Appears Every Year The algorithm is purely mechanical. Drill 2–3 examples from previous papers. GATE gives you the grammar and asks the table — this is a guaranteed 2 marks for anyone who practices it once.

The C Traps GATE Loves

30 Min Cap Software Engineering
~2–3 marks ▶

The Short List — Nothing More

  • SDLC models — Waterfall, Spiral, Agile (conceptual questions only)
  • Cohesion order (best→worst): Functional > Sequential > Communicational > Procedural > Temporal > Logical > Coincidental
  • Coupling order (best→worst): Data < Stamp < Control < External < Common < Content
  • Cyclomatic Complexity = E − V + 2P (P = connected components, usually 1)
  • Testing types — white box, black box, boundary value, equivalence partitioning
Seriously, 30 minutes max Software Engineering is 2–3 marks at most. Memorise the coupling/cohesion order mnemonic, do one cyclomatic complexity example, then move on. Every minute here costs you marks in OS or DSA.

The Mindset What actually separates scorers from panickers

GATE is not testing whether you know CS

It's testing whether you can retrieve what you've already learned under a time constraint. Two days of smart preparation is retrieval practice — not learning from scratch. There's a significant difference.

The 70/30 Rule for Last-Minute Prep

  • 70% of your time should be solving previous year questions — pattern recognition is the skill being tested
  • 30% should be refreshing formulas and closure property tables — the raw material for pattern recognition
  • 0% should be reading textbook chapters from the beginning — that time is gone and this isn't the moment

Physical Performance Matters Too

  • Study in 90-minute blocks — research consistently shows this is the natural cognitive peak window
  • Drink water — even mild dehydration measurably degrades working memory speed
  • Don't study past midnight — the hippocampus consolidates memory during sleep, not extra study hours
  • When your brain locks up on a topic — switch subjects immediately, return later. Pushing through foggy comprehension wastes time.
The Only Mindset That Moves Marks Confidence is not arrogance. It's the cognitive state in which your brain accesses stored knowledge fastest. Every exam-room panicker knows the material — they just can't access it. Breathe. You have this.
"The knowledge is already there.
The exam is just the retrieval test."

Two days, done right, is more than enough. Close this guide. Open a previous year paper. Time it. Check your answers. That loop — right there — is everything.
