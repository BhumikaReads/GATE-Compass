The MindsetWhat actually separates scorers from panickers

GATE is not testing whether you know CS

It's testing whether you can retrieve what you've already learned under a time constraint. Two days of smart preparation is retrieval practice — not learning from scratch.

The 70/30 Rule for Last-Minute Prep

  • 70% of your time solving previous year questions — pattern recognition is the actual skill being tested
  • 30% refreshing formulas and closure property tables — the raw material for pattern recognition
  • 0% reading textbook chapters from the beginning — that window is gone and this isn't the moment

Physical Performance Matters Too

  • Study in 90-minute blocks — research shows this is the natural cognitive peak window
  • Drink water — even mild dehydration measurably degrades working memory speed
  • Don't study past midnight — the hippocampus consolidates memory during sleep, not extra hours
  • When your brain locks up — switch subjects immediately, return later. Foggy comprehension wastes time.
The Only Mindset That Moves MarksConfidence is the cognitive state in which your brain accesses stored knowledge fastest. Every exam-room panicker knows the material — they just can't access it. Breathe. You have this.
"The knowledge is already there.
The exam is just the retrieval test."

Two days, done right, is more than enough. Close this guide. Open a previous year paper. Time it. Check your answers. That loop — right there — is everything.

Merge Sort — divide and conquer on [38, 27, 43, 3, 9, 82, 10]

Divide: [38,27,43,3] | [9,82,10] Sort L: [38,27]→[27,38] [43,3]→[3,43] → merge → [3,27,38,43] Sort R: [9,82]→[9,82] [10]→[10] → merge → [9,10,82] Final: merge [3,27,38,43] + [9,10,82] → [3,9,10,27,38,43,82]
Why stable? During merge, when left[i] == right[j], we ALWAYS take from the LEFT first — preserving relative order.

Binary tree traversals

1 / \ 2 3 / \ 4 5 Preorder (Root-L-R): 1 → 2 → 4 → 5 → 3 Inorder (L-Root-R): 4 → 2 → 5 → 1 → 3 ← sorted in BST! Postorder (L-R-Root): 4 → 5 → 2 → 3 → 1 Level (BFS): 1 → 2 → 3 → 4 → 5
Reconstruction rule: Inorder + Preorder → unique tree. Inorder + Postorder → unique tree. Preorder + Postorder alone → NOT unique.

Dijkstra's algorithm — trace

Graph: A→B(4), A→C(2), C→B(1), B→D(3), C→D(8) Initial: dist = {A:0, B:∞, C:∞, D:∞} Step 1: Extract A(0). Relax A→B: dist[B]=4; A→C: dist[C]=2. Step 2: Extract C(2). Relax C→B: min(4,3)=3✓; C→D: dist[D]=10. Step 3: Extract B(3). Relax B→D: min(10,6)=6✓. Step 4: Extract D(6). Done. Final: A=0, C=2, B=3, D=6
Negative weights → Dijkstra FAILS. Use Bellman-Ford instead. Bellman-Ford: relax ALL edges V−1 times.

Minimum Spanning Tree

Prim's MST
Grow from one vertex. Add cheapest edge connecting tree to non-tree. O((V+E) log V) with heap.
Kruskal's MST
Sort all edges. Add if no cycle (Union-Find). O(E log E). Better for sparse graphs.
Both produce same weight MST (may differ in structure if tie-weight edges exist). Both are greedy.

Chaining — trace

h(x) = x % 5. Insert: 10, 15, 20, 7, 25 Slot 0: 10 → 15 → 20 → 25 (all % 5 = 0) Slot 2: 7 (7 % 5 = 2)
Advantage: Simple deletion. Works well even at high load factors. α can exceed 1.

Open addressing — linear probing

h(x) = x % 5, probe: (h(x) + i) % 5 Insert: 10, 15, 20, 7 Key 10: h=0 → empty → Slot 0 [10, −, −, −, −] Key 15: h=0 → occupied → try 1 [10, 15, −, −, −] Key 20: h=0 → try 1 → try 2 [10, 15, 20, −, −] Key 7: h=2 → occupied → try 3 [10, 15, 20, 7, −]
Primary clustering: Long probe chains form. Use quadratic probing or double hashing to reduce clustering.
Deletion: CANNOT mark slot as empty — use tombstone/DELETED marker. Otherwise search chains break.

Build-Heap — why O(n) not O(n log n)

Most nodes are near the BOTTOM (leaves = 0 work). Height 0 (leaves): n/2 nodes × 0 work = 0 Height 1: n/4 nodes × 1 work = n/4 Height 2: n/8 nodes × 2 work = n/4 Total = n × Σ(k/2^k) = n × 2 = O(n) ✓
GATE trap: Build-Heap = O(n). Heap Sort total = O(n log n). Never say "Build-Heap is O(n log n)".

Master Theorem — the full formula

T(n) = aT(n/b) + f(n) where a ≥ 1, b > 1 Critical exponent: p = log_b(a) CASE 1: f(n) = O(n^(p−ε)) → T(n) = Θ(n^p) [leaves dominate] CASE 2: f(n) = Θ(n^p) → T(n) = Θ(n^p · log n) [tie] CASE 3: f(n) = Ω(n^(p+ε)) AND af(n/b) ≤ cf(n) → T(n) = Θ(f(n)) [root dominates]
Memory: Case 1 = leaves win → n^p. Case 2 = tie → n^p·log n. Case 3 = root wins → f(n).
NOT applicable when: n decreases by subtraction T(n)=T(n−1)+... Use substitution or recursion tree instead.
