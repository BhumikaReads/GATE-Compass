GATE is retrieval, not learning

It tests whether you can access what you've already learned under time pressure. Two days of smart prep is retrieval practice — not studying from scratch. Different job entirely.

The 70/30 Rule

  • 70% solving previous year questions — pattern recognition is the actual skill being tested
  • 30% refreshing formulas and closure tables — raw material for pattern recognition
  • 0% re-reading textbook chapters — that window is closed and this isn't the moment

Physical Performance Matters

  • Study in 90-minute blocks — natural cognitive peak; research is consistent on this
  • Drink water — mild dehydration measurably degrades working memory speed
  • Don't study past midnight — hippocampus consolidates during sleep, not extra hours
  • Brain locks up on a topic? Switch immediately, return later. Foggy comprehension wastes time.
The Only Mindset That Moves MarksConfidence is the cognitive state where your brain accesses stored knowledge fastest. Every exam-room panicker knows the material — they just can't access it. Breathe. You have this.
"The knowledge is already there.
The exam is just the retrieval test."

Two days, done right, is more than enough. Close this guide. Open a previous year paper. Time it. Check your answers. That loop — right there — is everything.

Merge Sort — Stable · O(n log n) guaranteed

Trace: [38, 27, 43, 3, 9, 82, 10] Divide: [38,27,43,3] | [9,82,10] Sort L: [27,38] + [3,43] → [3,27,38,43] Sort R: [9,82] + [10] → [9,10,82] Final: [3,27,38,43] + [9,10,82] → [3,9,10,27,38,43,82] ✓
Stability rule: During merge, when left[i] == right[j], always pick from LEFT first → equal elements keep original relative order.
Recurrence: T(n) = 2T(n/2) + n → Θ(n log n) [Master Theorem Case 2]

Quick Sort — Lomuto Partition on [10, 80, 30, 90, 40], pivot = last

Step 1: pivot=40 → partition → [10, 30, 40, 90, 80] Step 2: recurse left [10,30] → pivot=30 → [10, 30] Step 3: recurse right [90,80] → pivot=80 → [80, 90] Result: [10, 30, 40, 80, 90] ✓
NOT stable: Partitioning can reorder equal elements. Worst case O(n²): sorted array + last/first pivot.

Radix Sort — Non-Comparison · Stable · O(d(n+k))

Input: [170, 45, 75, 90, 802, 24, 2, 66] Pass 1 (Units): [170, 90, 802, 2, 24, 45, 75, 66] Pass 2 (Tens): [2, 802, 24, 45, 66, 170, 75, 90] Pass 3 (Hundreds): [2, 24, 45, 66, 75, 90, 170, 802] ✓
When to use: Integer keys with bounded range. Each pass must use a STABLE sort (Counting Sort). Radix inherits stability from the sub-sort.

Binary Tree Traversals

Example tree: 1 / \ 2 3 / \ 4 5 Preorder (Root-L-R): 1 2 4 5 3 → Serialize, copy tree Inorder (L-Root-R): 4 2 5 1 3 → Sorted output from BST! Postorder (L-R-Root): 4 5 2 3 1 → Delete tree (children first) Level-Order (BFS): 1 2 3 4 5 → Shortest depth, print levels
Reconstruction Rule: Inorder + Preorder → unique tree. Inorder + Postorder → unique tree. Preorder + Postorder ALONE → NOT unique (ambiguous when a node has one child).

AVL Tree — Self-Balancing BST

BF = Height(Left) − Height(Right). Must be ∈ {−1, 0, +1} at every node. Violation → rotate.

Four Rotation Cases

LL Case: BF(z) = +2, BF(left child) = +1. Left-Left heavy. Fix: single RIGHT rotation at z.
Before: z (+2) After RIGHT rotation: / \ y (0) y (+1) T4 / \ / \ x z (0) x T3 / \ / \ T1 T2 T3 T4

RR Case: BF(z) = −2, BF(right child) = −1. Right-Right heavy. Fix: single LEFT rotation at z.
Before: z (−2) After LEFT rotation: \ y (0) y (−1) / \ / \ z (0) x T2 x / \ / \ / \ T1 T2 T3 T4 T3 T4 Example: Insert 10, 20, 30 10 (BF=−2) → LEFT rotate → 20 with children 10,30
Memory: Lean Right → fall Left (single left rotation).
LR Case: BF(z) = +2, BF(left child) = −1. Kink inward. Fix: LEFT on left child, then RIGHT on z. Two rotations.
Step 1: LEFT rotate at y → straightens the kink (now looks like LL) Step 2: RIGHT rotate at z → same as LL case
Two rotations required. The "kink" (z left-heavy, y right-heavy) must be straightened first.
RL Case: BF(z) = −2, BF(right child) = +1. Mirror of LR. Fix: RIGHT on right child, then LEFT on z. Two rotations.
Step 1: RIGHT rotate at y → straightens the kink Step 2: LEFT rotate at z → same as RR case

Dijkstra's — Shortest Path (Non-negative weights only)

Like GPS: always process the nearest unvisited city first. Uses min-heap priority queue.

Graph: A→B(4), A→C(2), C→B(1), B→D(3), C→D(5) Step Extract dist[A,B,C,D] Updated 1 A (0) [0, ∞, ∞, ∞] A→C=2, A→B=4 2 C (2) [0, 3, 2, ∞] C→B=min(4,3)=3✓, C→D=7 3 B (3) [0, 3, 2, 6] B→D=min(7,6)=6✓ 4 D (6) Done ✓ Final: B=3, C=2, D=6
Negative weights → Dijkstra FAILS. Greedy assumption breaks: a later path via negative edge could beat a "finalized" path. Use Bellman-Ford instead.

Bellman-Ford — Handles Negative Weights

Relaxes ALL edges V−1 times (brute force). Time: O(VE). Detects negative cycles.

for i = 1 to V−1: for each edge (u,v,w): if dist[u] + w < dist[v]: dist[v] = dist[u] + w Run V-th iteration: if any distance still updates → NEGATIVE CYCLE exists
Use case: Currency arbitrage detection, routing protocols with negative costs.

Topological Sort — Only on DAGs

Like course prerequisites — must finish "Intro CS" before "Data Structures".

Kahn's Algorithm: A→B, A→C, B→D, C→D Step Indegrees Queue Order Action 1 A:0,B:1,C:1,D:2 [A] A Reduce B→0, C→0 2 B:0,C:0,D:2 [B,C] A B C Reduce D→0 3 D:0 [D] A B C D Done ✓ If final count < V → CYCLE exists → topological sort impossible
Only valid on DAGs. A cycle creates circular dependency — no valid start node exists.

Minimum Spanning Tree — Prim's vs Kruskal's

Prim's MST
Grow from one vertex. Add cheapest edge connecting tree to non-tree vertex. O((V+E) log V) with min-heap. Better for dense graphs.
Kruskal's MST
Sort all edges by weight. Add edge if no cycle (Union-Find). O(E log E). Better for sparse graphs.
Both produce same total MST weight. May differ in structure when tie-weight edges exist. Both are greedy algorithms.

Core Concepts

Hash function maps a key → index in array. Average O(1) for insert/search/delete. Collision: two keys hash to same slot.

TermDefinition
Load Factor αn (items) / m (slots). Higher α = more collisions.
Chaining avg searchO(1 + α)
Open addressing avgO(1/(1−α)) — degrades rapidly as α→1
Rehash thresholdα > 0.7–0.8 → double table size

Chaining (Separate Chaining)

Each slot = a linked list. Multiple keys with same hash go on same list. α can exceed 1.

h(x) = x mod 5 | Keys: 10, 15, 20, 25, 7 Slot 0: 10 → 15 → 20 → 25 (all mod 5 = 0) Slot 1: (empty) Slot 2: 7 (7 mod 5 = 2) Slot 3: (empty) Slot 4: (empty) Search 20: Slot 0 → check 10(no) → 15(no) → 20(yes) ✓
Advantage: Easy deletion. Unlimited load factor. Used internally in Python dict, Java HashMap.

Open Addressing — Linear Probing

Spot taken? Try next slot. And next. Until empty. Like a parking lot.

h(x) = x mod 5, probe: (h(x) + i) mod 5 Insert: 10, 15, 20, 7 Key 10: h=0 → empty → Slot 0 [10, −, −, −, −] Key 15: h=0 → taken → try 1 [10, 15, −, −, −] Key 20: h=0,1 taken → try 2 [10, 15, 20, −, −] Key 7: h=2 → taken → try 3 [10, 15, 20, 7, −]
Primary Clustering: Keys bunch together → long probe chains. Quadratic probing reduces this. Double hashing eliminates clustering entirely.
Deletion: CANNOT mark slot as empty — use DELETED/tombstone marker. Empty marker breaks search chains; tombstone lets probing continue past it.

Build-Heap — Why O(n) and NOT O(n log n)?

Build Max-Heap: [4, 10, 3, 5, 1] Step Heapify at What Happens Init — [4, 10, 3, 5, 1] 1 idx 1 (10) 10 already > children 5,1 → no swap 2 idx 0 (4) 4 < 10 → swap; 4 < 5 → swap again Final — [10, 5, 3, 4, 1] ✓ Max-Heap in O(n) Why O(n)? Most nodes are near the BOTTOM (leaves do 0 work): Height 0: n/2 nodes × 0 work = 0 Height 1: n/4 nodes × 1 work = n/4 Height 2: n/8 nodes × 2 work = n/4 Total = n × Σ(k/2^k) = n × 2 = O(n) ✓
GATE Trap: Build-Heap = O(n). Heap Sort total = O(n log n) because n×deleteMax dominates. NEVER say "Build-Heap is O(n log n)".

Heap Sort is NOT stable — but O(n log n) in ALL cases and O(1) extra space. Used in C++ IntroSort (Quick + Heap + Insertion hybrid).

Master Theorem — Recurrence Shortcut

T(n) = aT(n/b) + f(n) a = subproblems, b = shrink factor, p = log_b(a) Case 1: f(n) = O(n^(p−ε)) → T(n) = Θ(n^p) [leaves dominate] Case 2: f(n) = Θ(n^p) → T(n) = Θ(n^p · log n) [equal work every level] Case 3: f(n) = Ω(n^(p+ε)) → T(n) = Θ(f(n)) [root dominates]
Memory: Case 1 = leaves win → n^p. Case 2 = tie → n^p·log n. Case 3 = root wins → f(n).
NOT applicable: T(n) = T(n−1) + ... (subtraction, not division). Use substitution or recursion tree instead.

⚡ GATE Quick-Reference Card — High-Frequency Questions & Traps

These exact question patterns appear in GATE CS almost every year. Memorise the answer AND the why.

Q1
Which sort is stable?
Merge, Insertion, Bubble, Counting, Radix are stable. Quick, Heap, Selection are NOT. Equal elements are never crossed in stable sorts.
Q2
Best sort for nearly sorted data?
Insertion Sort — O(n) adaptive best case when data is nearly sorted. Only comparisons, few shifts.
Q3
Belady's Anomaly affects which algorithm?
FIFO only. More page frames can cause MORE page faults in FIFO. LRU and Optimal are immune.
Q4
Min comparisons to find BOTH min AND max?
3n/2 − 2 comparisons using the pair comparison trick (compare pairs first, then find min of losers and max of winners).
Q5
Quick Sort worst case?
O(n²) when input is sorted and pivot is first or last element. Fix: random pivot or median-of-three pivot selection.
Q6
Build-Heap time complexity?
O(n) — NOT O(n log n). Most nodes are leaves. Mathematical sum of work across all heights = 2n = O(n).
Q7
BFS vs DFS for shortest path (unweighted)?
BFS. DFS finds a path, not the shortest. BFS explores by distance — first time you reach a node is via shortest path.
Q8
When is topological sort valid?
DAG only (Directed Acyclic Graph). A cycle creates circular dependency — no linear order exists. Kahn's detects cycle if count < V.
Q9
AVL BF violation fix?
4 rotation cases: LL (1 right), RR (1 left), LR (left+right), RL (right+left). Restore BF ∈ {−1, 0, +1} at every node.
Q10
Open addressing load factor constraint?
Must be < 1 — table has finite slots. Chaining can exceed 1. Rehash around α = 0.7–0.8 to maintain O(1) performance.
Q11
Which traversals uniquely reconstruct a binary tree?
Inorder + Preorder, or Inorder + Postorder. Preorder + Postorder alone is ambiguous when any node has a single child.
Q12
Dijkstra vs Bellman-Ford — when to use which?
Dijkstra: O((V+E)log V), only non-negative weights. Bellman-Ford: O(VE), handles negative weights, detects negative cycles.
